# Catatan untuk Developer LLM — Fitur "Perdalam via AI" (Jaga Padi)

Fitur **"Perdalam via AI"** di aplikasi Jaga Padi mengirim hasil deteksi model visi — penyakit yang **sudah terkonfirmasi** (mis. `Hawar Daun 100%`, bisa multilabel) — beserta **7 parameter sensor tanah** (suhu, kelembapan, EC, pH, N, P, K + status aman/rendah/tinggi) ke endpoint `/api/chat`, dengan harapan memperoleh **diagnosa/anjuran LANJUTAN** untuk penyakit yang sudah pasti itu. Namun endpoint memperlakukan seluruh teks sebagai **gejala** dan **mengklasifikasi ulang**, sehingga mengembalikan hama yang berbeda dan sering keliru — pada uji nyata (durasi ~167 dtk), input "Hawar Daun" malah dijawab `prediksi.hama = "Penggerek Batang Padi"` (skor 0.35, `label_keyakinan: rendah`). Akibatnya jawaban AI **bertentangan** dengan hasil deteksi visi dan membingungkan petani; selain itu `narasi_gemma`/`pengendalian` tidak selalu muncul pada respons untuk query bergaya-instruksi seperti ini.

**Permintaan penyesuaian:** mohon tambahkan mode/parameter (atau endpoint baru, mis. `/api/pendalaman`) yang **menerima label penyakit yang sudah ditentukan model visi + konteks tanah** lalu menghasilkan narasi anjuran (kemungkinan penyebab, kaitan dengan kondisi hara/tanah, penanganan, dan **rekomendasi pemupukan**) **tanpa mengklasifikasi ulang** — perlakukan penyakit yang dikirim sebagai *ground truth* dan fokuskan Gemma pada penjelasan + rekomendasi. Idealnya menerima input terstruktur, mis. `{ "penyakit": ["Hawar-Daun"], "keyakinan": 1.0, "tanah": { "n": .., "p": .., "k": .., "ph": .., "ec": .., "kelembapan": .., "suhu": .. } }`, dan **selalu** mengembalikan `narasi_gemma` + `pengendalian` untuk penyakit tersebut. Dengan begitu hasil deteksi visi tetap otoritatif dan "pendalaman" menjadi relevan bagi petani.
